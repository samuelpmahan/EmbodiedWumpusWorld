# Teaching through deterministic meaning: bounded pilot

We ran one Luna-low pilot, then four separate learner sessions: Luna low/medium and Terra low/medium. Each learner answered a baseline before receiving a worked lesson and a transfer packet. Peak requested parallelism was four learner trials; each trial had two turns. No external model API loop or automatic retries were used. Learners were instructed not to use tools, other agents, files, or web. These are small demonstrations, not model rankings or evidence of durable learning.

## Deterministic substrate

The compiler materializes a finite joint world, computes its independent prior once, retains assignments compatible with every observation, normalizes their weights, then evaluates the query. It uses PxC, Tick receipts, and the existing probability atoms. The answer is never supplied by a language model.

Five concepts are covered: ambiguous breeze, conditional dependence, redundant observations, elimination by absence, and overlapping clues. The baseline uses prior .2. Transfer changes the prior to .3 and expands the fifth problem from three cells to four (breezes AB, BC, CD; query B).

The pilot baseline wrote the correct formula but added `.2 + .8*.04` as `.24` instead of `.232`. A worked-table correction did not prevent its transfer error: it reported total mass `.2601` rather than `.216`. That denominator equals P(AB breeze) × P(CD breeze), and therefore is consistent with dropping the middle BC condition; this is our diagnosis from its answer, not access to its internal reasoning.

In the four-way cohort, all learners listed the same eight valid transfer assignments. Luna medium nevertheless reported mass `.1278` and answer `.8521126761`; the correct values are `.216` and `17/24`. Thus its semantic certificate passed while its arithmetic failed. The verified compiler can calculate the correct probability from that validated interpretation. This is a system correction, not a new successful learner response.

## What to teach next

Ask for a checkable interpretation before a probability. Grade missing/extra assignments separately from numeric error. If an assignment fails, identify the particular breeze it violates. If the assignments pass but arithmetic fails, show the weight ledger and delegate arithmetic to the shared calculation. A duplicate clue must preserve the world set and posterior. Neither a fluent explanation nor “no confusion” is an acceptance condition.

There is no untreated comparison group, the four cohort baselines were already perfect, and the transfer task differs in difficulty. These results do not establish teaching efficacy, causation, model superiority, or retention. The structural-certificate requirement was introduced after the pilot and used consistently across the four cohort trials. Prompts and outcomes are retained below; response data normalizes numeric precision and assignment ordering, rather than claiming byte-for-byte transcripts.

## Learner protocol

Baseline: each cell independently has pit prior .2; sensors are perfect and refer to one static world. Ask P(A|breeze AB), P(A∧B|breeze AB), P(A|duplicate breeze AB), P(A|breeze ABC and no breeze BC), P(B|breezes AB and BC). Request JSON numeric answers, one-sentence reasons, and a confusion field. No lesson is included in that turn.

Lesson: the compatible baseline overlap assignments and prior masses are B=.128, AB=.032, AC=.032, BC=.032, ABC=.008. Total=.232; B mass=.200. Check each joint world once against all observations; normalize once; overlapping clues share one assignment. The pilot additionally received its explicit arithmetic correction.

Transfer: prior .3; first four question structures unchanged; fifth uses four cells with breezes AB, BC, CD and queries B. The cohort additionally supplies a certificate listing every surviving assignment and total prior mass. The correct transfer answer is withheld from learners until their answers are recorded.
